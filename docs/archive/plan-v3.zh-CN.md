## 2. 三条新增硬规则（v3 的执行前提）

1. **无 LIVE 绑定不算任务**：任务必须声明可启动的本地应用、窗口选择、运行后
   可读的应用记录面；没有这三样的任务只能用于 runner 自检，不能计入证据。
2. **无行为探针不算变体**：快照目录存在只证明“面被冻结”，不证明“行为已实现”。
   任何变体在跑任务前必须先通过 E1.5 行为探针，否则状态为 `NOT_RUNNABLE`，
   不得产出 0% 或 100% 的伪结果。
3. **无预注册端点不裁决**：每个阶段开跑前冻结端点表（主端点、N、MDE、否决线、
   停止条件）；数据出来后再改规则，本轮全部数据作废。

沿用 v2 的解耦要求：**不为任何应用、控件、对象写死判据；变体差异只由
`versions/surface-<id>/` 快照数据表达，代码只读快照 dispatch，不读变体 id。**

## 3. 执行路径：新增 E0.5 LIVE 适配层

v2 §3 的 `harness/run.py --surface S0 --tasks tasks-v5.json` 在当前装置中不成立：
它只跑 mock，且不存在一条把任务绑定到真实 UI 的路径。v3 把“能跑真实 UI”
作为独立工作包，先于任何基线。

### 3.1 LIVE 适配器（装置代理）

- 新增 `harness/run.py live`（或等价入口），契约沿用现有
  `subagent-prepare` / `subagent-collect` 的“模型侧只看 surface 快照”约定。
- 任务数据只带**启动规格**，不带应用名分支：
  `screen`、`launch{exe,args}`、`window_title`、`reset=restart`、`teardown=kill`。
  适配器按规格启动、按标题选窗、任务结束按规格清场；没有任何 `if app == ...`。
- 启动前：`somnus doctor` 必须报告子会话 live；不在 live 则
  `BLOCKED_CHILD_SESSION`，**不尝试主桌面**。
- 运行中：每个任务独立进程、独立窗口；窗口集合在启动前、断言后各取一次快照，
  用于确认“没有多开、没有残留、没有越界窗口”。
- 构建前置：`dotnet build apps/scenario-suite`；五屏各启动一次并 `observe` 到
  记录面（store 的 cart、form 的 records、tree 的状态行等）。
- **出口**：live smoke 3/3（同一屏连续三次启动—操作—断言—清场）；清场后窗口
  集合与启动前一致；泄露扫描 0；`selfcheck` 增加 live 项且全绿。

### 3.2 断言会话（装置代理）

断言不能复用被测会话的 ref，也不能读 fixture 内部状态。v3 规定：

- **运行后新开一个会话**（不是运行中的那个会话），`observe` 目标窗口，
  按语义查询读取**应用自己的记录面**（状态行、cart 列表、form 记录列表、
  输入框 value）。
- 语义查询只允许 `{role, name, in?}`，不允许任何 AutomationId、fixture 选择器、
  索引或窗口枚举序号；名称来自任务数据，解析走产品自身的 FIND 语义。
- 允许的断言原语收敛为四类：`read_text`、`read_value`、`child_names`（多重集）、
  `exists`。状态类断言语义化为“读状态行文本”，不再读内部 state 字段。
- 断言读取完成后再清场；断言产物只记“查询 + 命中行 + 判定”，不落原始整树。

**出口**：同一条任务连续 3 次，断言读到的记录面文本与参考解一致；把断言会话
从流程中移除时任务必须判失败（证明断言不是自证）。

### 3.3 清场与隔离（装置代理）

- 每任务重启应用；断言后 kill；窗口/进程集合前后快照比对。
- 子会话掉线：本次标记 `INFRA_DROPPED`，最多重跑 1 次；仍失败则停批，
  不静默切主桌面。
- 剪贴板、前台窗口按 v1 §5.2 恢复；不跨任务复用 ref。

**出口**：连续 12 次运行无跨任务状态残留；`INFRA_DROPPED` 0；泄露 0。

## 4. 任务面收敛

v5 的 27 条整体保留为 **mock 预演集**（只服务 selfcheck/oracle），不进入证据。
LIVE 任务另行派生为 `harness/tasks-live-v1.json`（任务代理产出；**本轮不改
`tasks-v5.json`**）。

### 4.1 类的 LIVE 处置

| 类 | LIVE 状态 | v3 处置 | 依据 |
|---|---|---|---|
| K1 deep-reach | 不可跑 | `MOCK_ONLY`；等 S5a/S5b 行为实现后再议 | 真实树 4 层 vs 任务 5 段；节点 id/状态文案/断言通道不符 |
| K2 offscreen | 条件可跑 | `LIVE_CONDITIONAL`：断言改多重集与语义名 | 真实行名 `Item 123 $2.50`；`expect_exact` 只认 `Item 123`；对加入顺序敏感 |
| K3 dynamic | 菜单可跑；对话框条件可跑 | `LIVE_CONDITIONAL`：菜单保留；对话框修 oracle 的 window 参数 | K3-003 oracle 第 4 步 `observe` 无 window；`FIND` 只作用当前窗口 |
| K4 read-then-write | 不可跑 | `MOCK_ONLY`；若追 Q5，先改形态（短值读取） | 真实编号固定 `REQ-0001`，无 224 字符只读值；表单初始为空且姓名必填 |

| K7 multi-field | 可跑 | `LIVE_OK`，本轮主类 | 真实 form 四字段 + 提交记录可读 |
| K8 large-list | 条件可跑 | `LIVE_CONDITIONAL`：同 K2 断言改写 | 同 K2 行名断言问题 |
| K9 cross-window | 不可跑 | `MOCK_ONLY`；跨窗口留给用户拍板 | 无两窗口协作屏；窗口 ref 按枚举顺序，不能用标题锁定 |

**LIVE 决策集最多 4 类：K2、K3、K7、K8**（三个屏族：store、menu/dialog、form）。

### 4.2 LIVE 任务的断言改写（任务代理）

- `child_names` 改为**多重集**比较（顺序不参与判定）。
- 行名比较取应用记录面的**实体名字段**，不比较含价格的整行；正文提到价格时
  单独用 `read_text` 取总价，不用名字行夹带。
- 所有 `selector` / `n_...` / `slot_...` / `win_...` 形态的断言语义化：
  `{role, name, in?}`；不得使用 fixture 生成的 id。
- K3-003 的 oracle 第 4 步补 `window`（从 `WINDOWS` 行取对话框 ref），
  并重跑参考解 3 次。
- K2/K8 的 oracle 不改变语义，只把断言口径对齐真实控件。

**出口**：每个 `LIVE_OK` / `LIVE_CONDITIONAL` 类在真实屏上参考解 3/3；
断言在参考解与两次人工扰动下都给出一致判定；`MOCK_ONLY` 类登记原因。

### 4.3 难度不加深（任务代理）

与 v2 §2 相反的一条：**本轮不因基线过高而加深任务**（K1 深度、K2 件数、
K4 只读值长度都不再动）。理由：v1 `baseline.md` §3 已证明继续加深会同时打死
弱变体，得到“全失败”而不是区分度。难度改用 §5 的天花板协议。

## 6. 难度与端点：天花板协议

### 6.1 为什么不再把 60%–95% 作为硬前置

v1 已测到 S0 = 100%，继续加深会打死弱变体。v3 把难度判定改为**分支**：

| S0 成功率 | 处理 |
|---|---|
| 60%–95% | 正常：成功率可作采纳端点 |
| ≥ 95% | **天花板**：成功率只作非劣性门槛；采纳只允许来自效率端点 |
| < 60% | 装置/环境问题：停，禁止靠放松断言压难度 |

天花板不是“任务合格”，而是“在报告里显式声明”：`CEILINGED`，并记录
“本轮不能以成功率区分变体”。

### 6.2 Headroom 预检（开跑前，执行代理）

每类在 S0 上先测 3 次，满足任一条才算“有头寸”，否则该类只作诊断：

- 工具回合 ≥ 参考解 + 1 的次数 ≥ 30%；
- 任务 token 的 CV ≥ 0.10；
- 无效调用率 > 0。

预检结果冻结到 `scratch/blackbox-toolset/prereg/v3-headroom.json`；没有头寸的类
不得成为效率主端点。

### 6.3 允许更换的难度杠杆（只换维度，不加深同类任务）

1. **接受天花板 + 效率端点**（默认）。
2. 降低 `max_steps`（12 → 9）——装置契约变更，只作校准，不用于裁决。
3. 更换被测主体（同族更弱档位）——只改主体，不改任务与变体；配对仍成立。
4. 环境扰动（视口更小、settle 更慢）——通用、不改任务文本；需先验证断言稳定。
5. 继续加深同类任务——**禁止**（v1 证据）。

前四项都属用户拍板项（§10.4）。

### 6.4 端点定义（预注册）

| 端点 | 定义 | 用途 |
|---|---|---|
| P1 成功率 | 断言全通过的任务运行占比 | 门槛/否决 |
| P2 语义/调用回合 | 每任务工具调用数（run 脚本内步骤另计“语义步”） | **主效率端点** |
| P3 token | 注入 + 完成 + 工具返回三分账本，任务总计 | 主效率端点（成本） |
| P4 无效调用率 | `ERR *` / 全部调用 | 仅在 S0 > 0 时用 |
| P5 墙钟 | 诊断，不裁决 | 不作端点 |

变体主端点预注册：S3a/S3b → P2；S1 → observe 回合（P2 的子集）；S2 → P1 非劣性
+ 参数误用；S5a/S5b → offscreen 类的 P2。其余端点只作描述。

## 7. 判定规则 v3

### 7.1 预注册

- 每阶段、每变体一份端点表（主端点、类清单、N、MDE、否决线、停止条件），
  冻结 hash 后开跑；存 `scratch/blackbox-toolset/prereg/`。
- 不做中途看数、不做阶段性“先采纳再补确认”。

### 7.2 成功端点

- 非天花板：采纳要求 `Δsuccess ≥ +15pp` 且配对 95% CI 下界 > 0（与 N=36 的
  MDE 对齐）；`+5pp ~ +15pp` 只记 `PENDING`，进入 confirm，不得直接采纳。
- 天花板：成功只作**非劣性门槛**：点估计下降 ≤ 5pp，且 95% 上界 ≤ 10pp；
  采纳不得引用成功率。
- 否决：汇总成功率下降 ≥ 10pp 且 CI 下界 > 0；或某一类下降 ≥ 20pp 且在
  ≥ 2/3 实例中出现。**单实例单次失败不再是否决线**（原 11pp 一票否决作废）。

### 7.3 效率端点

| 端点 | 采纳阈值 | 备注 |
|---|---|---|
| P2 回合 | 配对中位下降 ≥ 15%，且 bootstrap 95% 下界 > 0 | 或中位少 ≥ 1 回合 |
| P3 token | 配对中位下降 ≥ 10%，且下界 > 0；稳态每轮新增 ≤ 150 token | 两项同时满足 |
| P4 无效调用 | 仅在 S0 > 0：相对下降 ≥ 30% 且绝对下降 ≥ 1pp | S0 = 0 时只作护栏 |

### 7.4 特则（替换 v2 §4 中不可执行的部分）

- **S1**：主端点 observe 回合下降 ≥ 25%（配对、CI 下界 > 0）；护栏是 K8 类
  token 上升 ≤ 25%。护栏破了 → 只能写“条件采纳（仅 K3/K7 类）”。
- **S2**：主判据是成功非劣性 + 参数误用。基线误用为 0 时，用**绝对阈值**
  （≥ 2 次/10 任务或 ≥ 15%）判否决；基线 > 0 才用 2 倍相对阈值。
- **S5a/S5b**：offscreen 类回合下降 ≥ 15%，成功率不降；稳态固定成本
  （新增工具 schema/描述）单独列出，不折算进任务 token。两者都过时，优先
  token 中性且无解析错误的一种。
- **S3a/S3b**：回合下降 ≥ 15% 或 token 下降 ≥ 10%；**不再用“方差下降”**
  作为端点（N 太小，方差不可估），只作描述统计。
- **S4**：本轮无主端点（见 §10.6）。

### 7.5 小样本与 MDE

| N（配对观测） | 二值端点近似 MDE | 连续端点近似 MDE |
|---|---|---|
| 12（screening） | ~25pp | ~1.0 回合 |
| 36（decide） | ~12–15pp | ~0.5 回合 |
| 60（confirm） | ~8–10pp | ~0.4 回合 |

- 观测效应小于 MDE → 只写 `PENDING` 或 `NOT_DISTINGUISHABLE`，不得写“采纳”。
- 统计口径：以**任务实例**为重采样单位（重复嵌套在实例内），配对 bootstrap
  10k 次；不把 3 次重复当独立样本。
- 多端点：只对预注册主端点做裁决，其余标“描述性”，避免多重比较。

### 7.6 停止与作废

| 条件 | 动作 |
|---|---|
| 泄露扫描 > 0 | 立即停该条件，本轮作废 |
| surface/snapshot hash 漂移 | 停，重冻结 |
| 子会话掉线/UIA 异常/应用启动失败 | `INFRA`，重跑 ≤ 1，仍失败停批 |
| oracle 失败或断言不稳定 | `TASK_INVALID`，任务修复并重跑参考解，不进入裁决 |
| S0 LIVE 成功率 < 60% | 停，查装置/环境，禁止改断言 |
| 数据后再改规则 | 本轮数据全部作废 |

## 12. 风险与护栏

| 风险 | 缓解 |
|---|---|
| LIVE 应用跨任务残留 / 多开 | 每任务重启、前后窗口快照、kill 后确认集合一致 |
| 断言会话污染被测状态 | 断言另开会话；只读记录面；读后即清场 |
| 子会话掉线 | `INFRA_DROPPED`，重跑 ≤1，停批；不静默回主桌面 |
| S1/S2/S5 无行为却出结果 | E1.5 探针门；`NOT_RUNNABLE` 不进裁决 |
| 天花板被误读为“无差异即采纳” | 采纳只来自效率端点；成功只作非劣性门槛 |
| 小样本过判 | 预注册 MDE；低于 MDE 只写 `PENDING`；单次失败不否决 |
| 为通过而改任务/断言 | 任务变更必须先重跑参考解并重新冻结；数据事后不改规则 |
| 云端越界 | 白名单 + 前后快照 + 泄露扫描一票否决（沿用 v1/v2） |
| 实测数据堆积 | `runs-v3` 只留每轮 JSON 摘要 + 失败轮 transcript；超 50MB 先归档 |
| 变体靠 id 分支 | 代码只读快照 dispatch；新增变体只加目录 |

## 13. 术语

- `LIVE_OK`：有真实屏、参考解 3/3、断言稳定。
- `LIVE_CONDITIONAL`：有真实屏，但断言/oracle 需按 §4.2 改写后才能成立。
- `MOCK_ONLY`：本轮只在 mock 上存在，不能作为黑盒证据。
- `CEILINGED`：S0 成功率 ≥ 95%，本轮不以成功率为采纳端点。
- `NOT_RUNNABLE`：变体缺运行时行为或探针未过。
- `PENDING`：观测效应低于预注册 MDE，需 confirm 或放弃。
