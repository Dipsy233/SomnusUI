# 50 个用户任务与实测覆盖

记录时间：2026-11-07。设备名已脱敏为 `<COMPUTERNAME>`。Excel #11/#12 的结论记录于合成输入通道默认开启之前，引用前建议按当前剪贴板/键盘路由复核。

成功断言只检查运行时状态：文件内容、控件文本、窗口标题、进程存在、注册表值。

## 1. 适用范围

界面只要有控件，且控件发布了可操作接口，任务就能拆成能力调用完成，控件位于多深的子页面不影响该结论。

已知的系统性例外：输入框需要提交，且没有暴露提交按钮。Excel 编辑栏是典型例子：`set_text` 能写入控件，但单元格需要一次回车才接受，而本项目没有开放任意按键。应用发布一个确认按钮（`Invoke` 目标）时没有该问题；没有确认按钮时任务无法完成，运行时不会假装完成。

两类与能力边界无关、但会降低完成率的情况：

- 路径选择。一个任务可能有多条完成路径，模型不一定选择最短路径。App Pack 用于记录“这个应用的某件事该怎么做”，例如先选区域再调命令，或使用菜单/工具栏的哪一项。规则见 [../reference/packs.md](../reference/packs.md)。
- 界面不提供节点。画布不发布任何节点（画图的核心工作区）；自绘列表项可能不响应 `Invoke`（QQ 会话行只有右键菜单有效）。这些是应用侧事实。

下列 50 条用于实测，不代表能力上限。

## 4. 覆盖结论

- 常规控件、菜单、对话框、列表与设置页任务可以完成；成功判定来自运行时状态。
- 没有确认按钮的输入提交任务无法完成。
- 不发布节点的画布、部分自绘列表项无法完成。
- 依赖对话框导航层的保存/另存为任务在实测中失败。
- 部分结论早于合成输入默认开启；相关任务需要按当前配置复核。
