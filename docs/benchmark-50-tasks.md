# 50 个任务

成功断言只看运行时状态：文件内容、控件文本、窗口标题、进程存在、注册表值。

## 这份清单能得出什么

**绝大多数可以在 GUI 上完成的事情，SomnusUI 都能完成。** 界面只要有控件、
控件发布了可操作的接口，任务就可以拆成能力调用做完 —— 无论它藏在多深的子页面里。

已知的唯一系统性例外：**输入框要提交、而且没有暴露提交按钮。** Excel 的编辑栏是
典型：`set_text` 能把值写进控件，但 Excel 的单元格要等一次回车才收下，而本项目
没有开放任意按键。这类界面应用自己发布一个确认按钮（一个 `Invoke` 目标）就没有
问题；没有就做不完，运行时也不会假装做完。

两件不属于能力边界、但会让成绩单看起来更差的事：

- **绕远路。** 有的任务能从好几条路径做完，模型不一定挑到最短那条。这是模型对
  GUI 的熟悉程度问题，不是运行时缺能力。**App Pack 正是为此存在的**：把「这个
  应用的某件事该怎么做」写成提示（先选区域再调命令、走哪个菜单而不是哪个工具栏），
  模型就不必自己摸索。规则见 [packs.md](packs.md)。
- **界面本身不给路。** 画布不发布任何节点（画图的核心工作区），自绘列表项不响应
  `Invoke`（QQ 的会话行只有右键菜单有效）。这些是应用侧的事实，换任何驱动方式
  都一样。

下面 50 条是实测用的，不是能力上限 。
