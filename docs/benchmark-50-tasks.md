# 50 真实用户任务 × 语义 API vs 视觉坐标点击 对比基准

目的：在**同一批真实用户任务**上，公平对比两种 GUI Agent 驱动方式：

| 对照组 | 感知通道 | 动作通道 |
|---|---|---|
| **SomnusUI**（`--no-pack` 通用模式） | UIA 无障碍树 → SUI-Text（observe/find/inspect） | 语义能力 `CALL ref.cap()` |
| **Vision 基线** | 截图（同一 LLM 的视觉输入） | 坐标点击 / 键盘合成输入 |

公平性原则：
- **同一个模型、同一个 system prompt 模板、同一个 agent 循环**（examples/agent.py 复制一份换工具面）；
- SomnusUI 不用 pack（否则不公平——pack 是预训练的领域知识）；
- Vision 基线允许 zoom/裁剪重截（模拟真实视觉 agent 做法），但每次截图计入 token；
- 两者都通过**运行时状态断言**判成功（如文件存在、文本框内容、窗口标题），不接受模型自报。

## 二、对比协议

### 每个任务记录

```
{
  "task_id": 17, "group": "G3", "difficulty": 2,
  "agent": "somnus" | "vision",
  "success": true,            # 运行时状态断言
  "wall_time_s": 41.3,        # 端到端（含模型往返 + 执行）
  "llm_time_s": 38.1,         # 模型推理时间累计
  "exec_time_s": 3.2,         # 动作执行时间
  "prompt_tokens": 18400, "completion_tokens": 921,   # 累计
  "screenshot_tokens": 0 | N,  # vision 组：图片按该模型图片 token 计价折算
  "steps": 6,
  "tool_breakdown": {"observe": 2, "find": 1, "inspect": 0, "call": 3},
  "error": null | "..."
}
```

### token 口径（关键，必须写死）

- SomnusUI：所有 observe/find/inspect 返回文本 + system prompt，按 tokenizer 计数；
- Vision：每张截图按该模型的**图像 token 实际计费公式**折算（如 GPT-4o 分辨率公式、Claude `(w*h)/750`），并在报告中注明公式；
- 两者 completion 一视同仁；
- Vision 组记录 `screenshot_count` 和平均分辨率——允许 agent 自主决定截多大，但禁止低于模型最小可用分辨率作弊。

### 汇报指标

| 指标 | 说明 |
|---|---|
| 任务成功率 | 按难度分层（★/★★/★★★） |
| 中位 token / 任务 | prompt + completion 拆分；vision 单列图片 token |
| 中位耗时 / 任务 | 端到端 + 模型/执行拆分 |
| 一次通过率 vs 含重试 | 反映失败恢复成本 |
| token 随步数增长曲线 | SomnusUI 是 delta 增量，预期近似线性平缓；vision 每步全图，预期陡峭 |

### 预期假设（实验要证伪/证实的）

- H1：SomnusUI token/任务比 vision 低 ≥5×（observe 是文本 delta，截图每步全量重发）；
- H2：深层导航任务（G2）差距最大——vision 需要多次截图滚动探索；
- H3：SomnusUI 在 G4 的 CEF/自绘应用上有短板（树萎缩），vision 可能反超——如实报告；
- H4：耗时主要由模型推理决定；SomnusUI 文本延迟更低，但若 vision 用更快的小模型则另计（保持同模型）；
- H5：G5 窗口切换组，两者都必须把窗口带到前台（SomnusUI 也会，见 [interactive-usage.md](interactive-usage.md) 的“使用前先把窗口提到前台”）；差异在于 SomnusUI 只需一次 UIA 切换，不需要指针移动和等待渲染。

### 公平性红线

1. 同一模型、同一温度（建议 0）、同一 max_tokens；
2. Vision 基线实现要认真（截图 + SetCursorPos 点击 + SendInput 键盘），不许故意做弱；
3. 每任务跑 3 次取中位，环境预置脚本化（文件/窗口状态可复位）；
4. 断言只看运行时状态，代码里不出现"从 LLM 文本判断成功"。

## 三、落地结构

```
bench/
├── tasks_50.py           # 任务定义：指令、目标应用、断言函数、环境预置/复位
├── agent_somnus.py       # 复用 examples/agent.py，no-pack
├── agent_vision.py       # 截图 → 模型 → 坐标动作 → SetCursorPos/SendInput
├── metrics.py            # token/时间采集、图片 token 折算
├── run_compare.py        # 跑批 + 汇总报告（JSON + markdown 表）
└── results/              # 逐任务逐次原始记录
```

运行：`python -m bench.run_compare --tasks all --runs 3 --model xxx`
